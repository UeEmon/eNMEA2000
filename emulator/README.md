# 独立Docker TCP/UDPエミュレータ

macOSではリポジトリのルートで `bash verify-macos.sh` を実行すると、本体とエミュレータの起動、TCP連接と保存の自動確認まで一括で行えます。

本体システムを起動した後、プロジェクトのルートで `docker compose -f emulator/compose.yaml up -d --build --wait` を実行します。エミュレータ画面は `http://localhost:8090` です。

エミュレータの地図は本体と同じCesiumJSと、同梱のNatural Earth背景図を使います。地図の「開始位置を置く」を選んでクリックすると送信位置を設定できます。「航路点を追加」でクリックした順に最大30点の航路を作ります。マーカーのドラッグで開始位置／航路点を修正し、「針路を指示」で現在位置からクリック地点への針路を設定できます（航路は解除されます）。送信中の地図編集も次の送信から反映します。

Web画面で対地速度（ノット）、針路（度）、AIS船舶数（1～20）、送信間隔（0.2～60秒）、航路周回を指定できます。メッセージタイプのタブ（RMC、GGA、AIS Type 1、AIS Type 5）では、タイプごとに送信の有効・無効を切り替えられます。選択後は「送信開始・設定反映」を押して反映します。タブは左右矢印キー、Home、Endでも切り替えられます。AIS Type 5は開始時と60回ごと、他の有効なタイプは毎回送信します。TCPはCRLF区切りのストリーム、UDPはNMEA 1文ごとにCRLF付きデータグラムで送信します。停止するとTCP接続を閉じます。接続先は環境変数 `NMEA_TARGET_HOST` と `NMEA_TARGET_PORT` で指定します。

別のComposeプロジェクトとして起動し、独立したDockerネットワークから `host.docker.internal:10111` に接続します。`extra_hosts: host-gateway` はLinuxのGitHub Actionsでも同じ経路を使うための指定です。Web UIは既定でローカルホストのみに公開します。画面の「送信先（コンテナ外部）」からIPアドレス／ホスト名・ポート・TCP/UDPを設定します。保存すると通常送信と自動周回を停止します。設定は専用Dockerボリュームに保存し、コンテナ再作成後も維持します。環境変数は保存済み設定がない場合の初期値です。

端末のPython 3.12から `python scripts/smoke_emulator.py` で2つのCompose間のTCP送信・GIS航路追従・AIS位置情報保存を検証できます。GitHub ActionsではさらにブラウザからCesium地図をクリックして航路・位置がサーバへ反映されることを検証します。用途はシステム試験です。実際のAIS送信器ではありません。

航路末尾に到達すると送信位置を保持して速力0ノットを出します。「航路を周回」を選ぶと先頭の航路点へ戻ります。出力するAIS船舶は基準位置から固定の間隔を空けて同じ航路に沿って移動します。疑似データであり衝突回避や航海判断には使えません。

## AIS 全Type試験

画面の「AIS 全Type試験」で項目を選び「選択項目を送信」、または「全項目を送信」を押します。定期送信を開始しなくても使えます。Type 1～28と旧形式Type 0の29種類を、42項目・45文の固定NMEA文で送信します。Type 5と26の分割文、Type 24 Part A/B・補助船舶、Type 25/26の宛先指定と構造化の組み合わせ、Type 17の負の座標・位置利用不可、Type 22/23の海域指定を含みます。

画面の完了表示は送信処理が済んだことを意味します。UDPは相手の受信を保証しません。受信後の解析・保存は本体のデータ画面で確認します。試験文は `emulator/ais-all-types.log` と `emulator/ais_suite.py` に固定し、送信順とチェックサムを再現できます。同じTypeを繰り返すと本体のイベント件数は増えます。テスト対象の船舶データベースに疑似MMSIが記録されます。

全項目送信では試験中心の緯度・経度と同心円の間隔（0.2～20海里）を指定します。地図操作の「試験中心を置く」でも指定できます。42項目は半径1・2・3倍のリングに7・14・21点ずつ等角度で配置され、Cesiumにシンボルと円を描画します。各試験文に固有のMMSIを付けてチェックサムを再計算し、続けて同じMMSIのAIS Type 1位置通知を送ります。位置を持たないTypeも本体GIS上で各試験項目の位置として確認できます。全項目送信は計87文です。個別送信は元の固定文のままです。リングの位置は疑似配置であり、元の試験文の位置・海域フィールド自体を変更するものではありません。

「全項目を送信」で全項目を一度送信すると同時に自動周回を開始します。シンボルの各更新時に最新位置・速力・針路のAIS Type 1文を生成し、選択したTCP/UDPで継続送信します。「送信停止」（航路設定側の「停止」でも可）で周回・通常の定期送信を停止し、TCP接続を閉じます。全リングを同じ角速度で時計回りに動かすため、各リング上のシンボル間隔を維持します。ブラウザを閉じても送信は続き、再表示で現在位置を取得します。中心・リング間隔の変更は停止してから行います。

自動値は試験向けの負荷と視認性を考慮した計算です。最も密なリングのシンボル間隔を約120秒で進む角速度を基準に、外周速度を80kt以内とします。更新は1秒以上・毎秒60位置文以下を基準とし、実測の生成・TCP書き込み時間の4倍以上へ調整します（上限10秒）。経過時間から移動角度を計算するため更新間隔の変更で速力は変わりません。画面に算出した更新間隔・角度・外周移動量を表示します。接続障害時は再接続し、再接続待ちの時間は移動に加算しません。静的な試験文の全フィールドを毎周期再送するものではありません。

## Mac Docker DesktopからiPad・LAN端末への送信

```sh
git pull
docker compose -f emulator/compose.yaml up -d --build --wait
```

1. MacとiPadを同じLANに接続し、iPadアプリを前面で起動します。アプリの設定に表示されるLANのIPアドレスを確認します。
2. `http://localhost:8090` の送信先にそのIPを入力し、TCP / 10111 または UDP / 10110を選んで保存します。
3. 通常の「送信開始・設定反映」、AIS個別送信、または「全項目を送信」で試験します。全Typeの位置更新も同じ送信先へ停止ボタンまで継続します。

外向き通信のため送信先ポートのDocker公開は不要です。`localhost` はコンテナ自身を指します。Mac上の受信アプリへは `host.docker.internal`、LAN端末へはその端末のIPを指定します。接続できない場合は受信側の待受ポート、ローカルネットワーク権限、ファイアウォール、Wi-Fiの端末間通信制限を確認します。IPv4・IPv6・ホスト名を指定できます。Web画面8090、本体Web18081、コンテナ内の本体Web80は従来通りです。
